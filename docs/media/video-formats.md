# 视频格式介绍

视频格式通常指文件的**封装格式**，例如 MP4、MOV、MKV。封装格式负责把视频、音频、字幕和元数据组织在一起；**编码格式**则决定音视频如何压缩和还原。

## 封装与编码的区别

可以把封装理解成容器，把编码理解成容器中内容的存储方式。例如，一个视频文件可以由以下部分组成：

| 层次 | 示例 | 作用 |
| --- | --- | --- |
| 封装格式 | MP4（`.mp4`） | 组织媒体轨道、时间信息和元数据 |
| 视频编码 | H.264 / AVC | 压缩与还原画面 |
| 音频编码 | AAC | 压缩与还原声音 |

因此，同样是 `.mp4` 文件，内部可能采用不同编码，设备不一定都能播放。播放器需要同时支持封装和内部编码；编码的规格、位深、分辨率等也会影响兼容性。参见 [MDN：媒体封装格式](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Containers)。

## 常见封装格式

| 格式 | 常见扩展名 | 特点 | 常见用途 |
| --- | --- | --- | --- |
| MP4 | `.mp4` | 兼容范围广，可封装不同音视频编码 | 日常拍摄、分享、网页播放 |
| MOV | `.mov` | QuickTime 容器，常见于苹果设备和剪辑流程 | 素材录制、视频剪辑、素材交换 |
| MKV | `.mkv` | 支持多条音轨、字幕、章节和附件 | 多语言视频、本地视频收藏 |
| WebM | `.webm` | 面向网页，常搭配 VP8、VP9 或 AV1 视频编码 | 网页视频、在线内容 |
| AVI | `.avi` | 较早的容器，现代网页原生播放支持有限 | 旧设备、旧软件和历史素材 |
| MPEG-TS | `.ts` | 面向传输，可复用多路媒体流 | 广播电视、流媒体分片、电视录制 |

格式名称不代表固定画质或文件大小。例如，MOV 可以保存高码率剪辑素材，也可以保存压缩视频；MKV 也不等于无损视频。封装能力可参考 [MDN 文档](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Containers)和 [Matroska 官方介绍](https://www.matroska.org/what_is_matroska.html)。

## 常见视频编码

| 编码 | 特点 | 使用时关注 |
| --- | --- | --- |
| H.264 / AVC | 使用广泛，兼容设备和软件较多 | 常用于日常交付与分享 |
| H.265 / HEVC | 相近画质下通常比 H.264 更节省码率 | 接收设备的解码能力、软件支持 |
| VP9 | 常用于网络视频，可封装在 WebM 中 | 浏览器和设备的解码支持 |
| AV1 | 注重压缩效率，用于网络视频分发 | 编码耗时、硬件解码支持 |

压缩效率还取决于画面内容、编码器实现和参数，不能仅凭编码名称预测最终效果。浏览器和操作系统支持会变化，具体交付前可核对 [MDN：视频编码指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Video_codecs)，并在目标设备上试播。

## 什么决定画质和文件大小

- **分辨率**：画面的像素尺寸，例如 1920 × 1080；分辨率高不保证源素材清晰。
- **帧率**：每秒画面数量，例如 24、30、60 fps；帧率更高通常需要更多数据维持相近画质。
- **码率**：每秒存储的数据量。在相同编码和相近设置下，码率会影响压缩失真和体积。
- **编码与参数**：编码器、压缩设置、位深等会影响画质、体积与处理速度。
- **源素材**：失焦、噪点和已经丢失的细节，无法仅靠换格式恢复。

文件大小可按平均总码率粗略估算：

```text
文件大小（MB）≈（平均视频码率 + 平均音频码率）（Mb/s）× 时长（秒）÷ 8
```

例如，总码率为 8 Mb/s、时长为 60 秒的视频，媒体数据约为 60 MB。这里使用十进制单位，未计入封装、字幕等额外开销。

## 按用途选择

| 用途 | 选择思路 |
| --- | --- |
| 日常分享、演示播放 | 可先考虑 MP4 + H.264 + AAC，并在接收设备上试播 |
| 视频剪辑、后期制作 | 按剪辑软件和协作流程选择容器与编码，保留原始素材 |
| 多音轨、多字幕收藏 | 可考虑 MKV，确认播放器支持所需音轨和字幕 |
| 网页视频 | 按目标浏览器选择 MP4 或 WebM，必要时提供多个版本 |
| 上传内容平台 | 核对平台的封装、编码、分辨率、帧率和码率要求 |

## 常见误区

- **改扩展名就是转换格式**：把 `.mkv` 改成 `.mp4` 不会改变文件内部结构。
- **换封装一定损失画质**：仅重新封装、直接复制原有媒体流时，不会因重新压缩损失画质，但音轨、字幕等必须得到目标容器支持。
- **转码可以提高原始清晰度**：有损转码通常会增加损失；提高分辨率或码率不会自动恢复已经丢失的细节。
- **文件越大，画质越好**：不同编码、素材、时长和音轨配置之间，不能只用体积比较画质。
